Foobara is a Ruby framework built around a single powerful idea: every domain operation is a **Command**. Commands carry formal, machine-readable metadata about their inputs, outputs, and errors — making your entire system discoverable. That discoverability lets Foobara abstract away integration code so you write your domain logic once and use it from anywhere: a Rack API, a Rails route, a shell CLI, a Model Context Protocol server, an async job queue, or a remote TypeScript client.

## Why Foobara?

Traditional applications scatter business logic across controllers, jobs, service objects, and serializers. When you need to expose that logic through a new channel — say, an MCP tool or an async worker — you write more glue code, often duplicating validation and error handling.

Foobara solves this by making **Commands** the single source of truth for every domain operation:

## Get Started

<Steps>
  <Step title="Install Foobara">
    Add `gem "foobara"` to your Gemfile and run `bundle install`, or generate a full project with `foob generate ruby-project --name your-org/your-project`.
  </Step>
  <Step title="Write your first Command">
    Subclass `Foobara::Command`, declare typed inputs with the `inputs` DSL, a `result` type, and implement `#execute`.
  </Step>
  <Step title="Connect it to the outside world">
    Choose a connector — Rack, Rails, CLI, or MCP — call `connector.connect(YourCommand)`, and you're live.
  </Step>
  <Step title="Explore discoverability">
    Hit `/manifest` on your running server or call `.foobara_manifest` in code to see the full machine-readable description of your system.
  </Step>
</Steps>
